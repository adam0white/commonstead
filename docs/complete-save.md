# Complete saved games

Native play writes one current gzip Blob to IndexedDB. The record includes its exact decoded byte count, SHA256 and a revision. Decoding verifies all metadata and original JSON bytes before replay. The prior localStorage wrapper remains unchanged during migration. Native save failures leave the prior save and complete download available.

The current record is bounded to64MiB compressed and64MiB expanded. File selection, expanded JSON and current JSON use the same64MiB ceiling from the complete-source archive codec. Original file bytes plus current JSON are bounded to128MiB. A compressed file is streamed and refused as soon as expansion exceeds the bound. Existing stricter schema, source-list and input-count limits also apply. The limits describe retained data. They do not bound all transient JavaScript objects or guarantee quota on every device.

The write queue retains one active candidate and one replaceable pending candidate. Superseded pending callers resolve without adoption and release their complete strings. Each candidate is independently bounded to64MiB expanded; the two candidate strings therefore carry at most128MiB of UTF8 data, in addition to the bounded prior save. Each write compresses an immutable local-save string. After compression it checks the native entry and source metadata again. A single read/write transaction compares the held revision with the stored revision, then stages the replacement. The final request checks the entry and source again before automatic commit. Quota, stale metadata and another tab's write abort the candidate. They do not replace the previous record.

The file route retains exact original bytes, filename, MIME type, modification time and SHA256. Its current run remains separate from native persistence and resident ownership. Cancel, replacement selection, navigation and hidden-page events invalidate pending adoption. Full and compact files run the existing validators. No native history is clipped.

Public HF archive admission runs in a terminable worker. Host replay uses the same generator implementation as synchronous imports, with event-loop boundaries between actual native steps. It reconstructs a real Run through public operations and compares the entire resulting archive with the selected archive. Only that reconstructed live Run can be adopted. No worker-owned Run crosses realms. The worker cannot publish people or write saves.
